# Trackpad 质感升级：AGSL Liquid Glass

## 背景与第一轮的失败

当前 `TrackpadScreen` 的视觉是「纯色背景 + 不透明圆角卡片」，希望做出接近
Apple Liquid Glass 的质感。

第一轮并行试了三个方案（全屏封面铺底 / 氛围渐变光斑 / 卡片材质强化），
**全部失败**。三者的共同问题：都是「半透明 + 渐变 + 描边」这套 CSS
glassmorphism 的做法，做出来只是磨砂卡片，与玻璃无关。

**根因**：真正的 liquid glass 核心是**折射**——背景要被玻璃边缘的曲面
扭曲、放大、产生色散，而不只是被模糊。这是 GPU shader 的活，
Modifier 堆叠做不出来。

三个失败变体的代码已全部丢弃。但其中两个发现是真问题，需在本轮修正：

1. 触点绘制的 `radius = 48f` 是**像素**写死的，在 xxhdpi 上只有 16dp，
   在 mdpi 上是 48dp——同一份代码在不同机型上差三倍
2. 通知监听服务的 `android:label` 与应用名共用字面量 `"nudge"`

## 技术方案

**AGSL + `RuntimeShader`**，手写 shader，不引第三方库。

### 核心机制

1. **SDF 驱动的边缘折射**——圆角矩形的有符号距离场 `sdRoundedBox`，
   距边缘的距离决定折射强度。扭曲因此是**贴着边框的一圈**，中央是平的。
   这与真玻璃一致：中央平板区不折射，只有边缘曲面折射。
2. **距离场的梯度就是表面法线**，决定折射方向与高光角度，过圆角时不失真。
3. **顺序：先模糊，后折射**。折射作用在已模糊的内容上才读作「厚玻璃」；
   反过来是「一张模糊贴纸」。第一轮三个变体都缺这一步。
4. **色散**——R/G/B 三通道各偏移采样，边缘产生棱镜彩边。
5. **中央保持清晰**——歌词是本应用主要可读内容，不能整块糊掉。
   这正是 SDF 方案的天然行为，无需额外处理。

### 背景采样的结构约束

Android 的 `RenderEffect` 只能采样**图层自身的内容**，采不到图层背后的像素
（Android 没有 Windows `CreateHostBackdropBrush` 那样的合成器级接口）。

因此必须走**父层方案**：把要被折射的内容（歌词层）放进挂了
`renderEffect` 的 `graphicsLayer` **内部**，shader 通过
`uniform shader` 拿到整个图层的内容，对边缘区域做折射，中央原样输出。

`rememberGraphicsLayer()` + `toImageBitmap()` 的快照方案**不可用**：
它需要 Compose UI 1.7.0-alpha07+，本项目是 1.6.1（BOM 2024.02.00）。

## API 级别：明确放弃降级

`RuntimeShader` 要求 **API 33+（Android 13）**，本项目 minSdk 是 26。

**本次明确不做降级适配**——这是作者自用工具，目标设备是
三星 SM-G9810 / Android 13 / API 33。API < 33 时走一条最简兜底路径
（当前的不透明 surface 外观），只需保证不崩，不追求观感等价。

这与项目既有的两处 blur 降级（API 31+）不同：那两处降级后仍可用，
本次降级后就是普通卡片。这个取舍已与作者确认。

## 交付物

### 一、玻璃 shader 与 trackpad 集成

触摸区改造为：边缘折射 + 色散 + 镜面高光的玻璃，中央清晰透出歌词。

触点反馈与手势命中反馈同步改为玻璃语言（局部亮度扰动 / 光晕），
并修正上述 dp/px bug。

### 二、调参实验室（临时）

设置页新增「玻璃实验室」入口，内含 shader 效果预览 + 参数滑块，
可在真机上实时调节：折射率、边缘带宽、色散强度、模糊半径、
圆角指数、高光强度等。

**存在理由**：这类效果的成败全在参数，而实现者看不到屏幕，
盲调必然要往返多轮。有滑块作者两分钟即可调定。

**生命周期**：参数调定后，数值固化进 trackpad，此入口**予以删除**。
它是脚手架，不是产品功能，不写进 README，不做持久化存储。

## 硬约束

1. **不得修改 `GestureRecognizer`**，及其「纯 Kotlin、不依赖 Android 类」的性质
2. **不得改动触摸链路的接线方式**：触摸区 `Box` 上的 `pointerInteropFilter`
   保持原样，不得插入新的 pointer 修饰符或拦截触摸
3. **不引入任何第三方依赖**
4. **不改动 `LyricsOverlay.kt` 的排版逻辑**——它只作为被折射的内容存在
5. **歌词中央区域必须保持清晰可读**——这是本应用的主要可读内容
6. 深色 / 浅色两种主题下都要成立
7. 不改动 release 构建与发布流程
